# Reflection Answers

## Challenges & Reflections

One of the main challenges I experienced in this laboratory was understanding the difference between the procedural mysqli approach and PDO. With mysqli, I had to work with the connection object, prepared statements, `bind_param()`, result objects, and functions such as `mysqli_fetch_assoc()`. At first, the number of steps made the code feel longer and easier to mix up. PDO felt more consistent to me because parameters can be placed directly inside the `execute()` array and rows can be fetched as associative arrays by default. I also noticed that both approaches still require careful handling of user input and database errors, so changing the API does not remove the need for good programming practices.

Parameterized queries were another important lesson. Instead of directly placing user input into SQL strings, placeholders are used and the values are supplied separately. This makes the SQL easier to control and helps prevent SQL injection. I also learned why the UUID primary key needs special handling. The student ID is a string with a fixed UUID format, so it should never be converted to an integer. If it were cast to an integer, the value could become `0`, causing the database lookup to fail. Since the ID is generated by `UUID()` during insertion, there is also no auto-increment ID to retrieve with `insert_id` or `lastInsertId()`.

The ENUM field also helped me understand how application validation and database constraints work together. The form accepts only `Male` or `Female`, matching the values defined by the database. Server-side validation checks this before attempting the insert or update.

Between the two approaches, I prefer PDO for a real project because I find its prepared-statement syntax cleaner and its configuration makes error handling and fetching behavior explicit. However, working with mysqli was still useful because it showed me the lower-level steps involved in database programming. Overall, this activity helped me understand that CRUD is not only about making pages that can add, display, edit, and delete records. It also involves validation, safe queries, correct data types, error handling, and protecting the integrity of the database.
